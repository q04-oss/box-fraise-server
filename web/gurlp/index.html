An API for consented attention.

Stripe moves money. gurlp decides when it is allowed to move — only when somebody consented to give their attention, and only in a form both parties signed for.

Pay to reach. Get paid to attend.
Both consent. The moment is recorded.

Advertising is the first thing it is used for. It is not the definition.

Five rules

These are the product. Everything else is an implementation detail.

  1. No view from above.A report is one account's local view of the events it took part in. There is no endpoint that returns everything, and nobody — including whoever runs the server — gets a global picture.
  2. Routing distributes, never targets.Pings go to the next available recipient, oldest first. No profiling, no scoring, no optimising for open rate. The routing code does not read the events table.
  3. Denials are free, silent and unrecorded.No event, no counter, no column. A refusal is indistinguishable from never having looked, because nothing is written either way.
  4. Every mutation is signed.Ed25519, verified before the charge and before the insert. Not optional, not skipped when absent. The key that signs is the identity.
  5. Reports contain only co-signed events.Never inferred interest, never lookalikes, never a fact about somebody who did not sign. One of those breaks the model.

The atom

An event exists only because two people both acted and both signed: the sender over their ping, the recipient over their open. It is immutable in the database — a record of consent that can be edited afterwards is not one.

A report is computed from events and stored nowhere. There is no reports table. Two accounts who share an event see the same facts, centred differently — they cannot disagree, because both views are drawn by one query.

The sender is told attention arrived, never whose. A recipient knows who paid them, because being paid tells you that. Those are the only facts both parties hold, and they are exactly what a report contains.

Signing

No session, no cookie, no bearer token. A signature over a canonical message, which binds the terms — a signature made for a ping at a dollar cannot be lifted onto the same ping at a cent.

# what a sender signs to create a ping
gurlp:ping:v1|<ping_id>|<sha256(sealed)>|<price_cents>|<opens_sought>

# what a recipient signs to open one
gurlp:open:v1|<event_id>|<ping_id>|<recipient_id>

# and to read anything at all
gurlp:req:v1|<METHOD>|<path>|<nonce>
curl -X POST $GURLP/pings -d '{
  "ping_id":     "…",   // chosen by you, and signed
  "sealed":      "…",   // opaque. gurlp never reads inside it
  "price_cents": 45,     // integer cents, never floats
  "opens_sought": 100,
  "signature":   "…"
}'

The surface

POST /accountsA Stripe Connect id and a public key. That is the whole signup — no username, no password
POST /pingsSend. Charged for the quota before it goes live, so a recipient is payable the instant they consent
GET /inboxRoute and deliver. Sealed — what is inside arrives on consent, not before
POST /pings/{id}/openConsent. Creates the event, pays the recipient, returns the content
POST /pings/{id}/denyRefuse. 204, and nothing written anywhere
GET /reportsThis account's own view. There is no parameter for whose — the signature decides

What is true today

The service is written and running: Rust, Axum, Postgres. Migrations, the four endpoints, mandatory signature verification, and a test suite covering forged signatures, denial leaving no trace, quotas filling, and two reports agreeing about a shared event.

Payments sit behind a trait with a Stripe implementation and a mock. It runs on the mock by default and says so at boot. The Stripe half is written against Stripe's REST shapes and has not yet met a live key.

It is deployed and answering:

curl https://gurlp-api-production.up.railway.app/health
ok

No money moves through it. That instance runs the mock, so a ping charges nobody and an open pays nobody. There is nothing to sign up for and no keys to request — registration is open, which is exactly why it is not carrying anybody's money yet. The app is a working drawing of a client and talks to nothing.
